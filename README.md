# Чистый дом

Учебный прототип сайта клининга: HTML, CSS, JavaScript, Express, Sequelize и SQLite.
Пять страниц, регистрация, вход, заявки, текстовый поиск и защита из задания.

## Запуск

Нужны Node.js **22.16 или новее** и npm. Команды выполняются в папке проекта:

```sh
npm ci
npm start
```

Откройте **http://127.0.0.1:3107**. Остановка сервера — `Ctrl+C`.
Сборка интерфейса не нужна. Для первоначальной установки пакетов нужен интернет;
после установки приложение работает локально без внешних сервисов и CDN.

При установке драйвер `sqlite3` загружает готовую библиотеку для вашей системы.
Установочные скрипты npm должны быть разрешены: флаг `--ignore-scripts`
для этого проекта использовать не нужно.

Настройки заданы константами: `port` и `host` в `src/server.js`,
`dataDir` в `src/db.js`. Файлы конфигурации создавать не нужно.
Пути `data/` и `public/` отсчитываются от папки проекта; запускайте сайт
командой `npm start` из этой папки.

Папка `data/` создаётся автоматически. В ней находятся база `cleaning.sqlite`
и случайный секрет сессий. Аккаунты и заявки сохраняются после перезапуска.
Для чистой демонстрации остановите сервер и переместите `data/` в резервную папку.

## Как посмотреть работу

1. На главной прочитайте уведомление о cookie и нажмите «Понятно».
2. Зарегистрируйте вымышленного пользователя, например:
   фамилия `Иванов`, имя `Иван`, отчество `Иванович`, логин `Student`,
   пароль `Study2026!`, телефон `8(999)123-45-67`, email `i@mail.ru`.
3. Отметьте согласие, войдите и создайте заявку с адресом и датой.
4. Обновите страницу: заявка останется в кабинете. Нажмите «Выйти».
5. В поиске проверьте `уборка` и `.*`: второй запрос будет отклонён.

Учётных записей по умолчанию нет. Админка, отзывы, оплата и слайдер не входят
в этот сокращённый прототип. Все поля регистрации обязательны. Ограничение
email в 20 символов взято из дополнений к заданию.

## Проверка защиты в браузере

Локальный прототип запускается по HTTP. Сертификаты и дополнительные режимы
запуска не нужны. Настройки для реального размещения по HTTPS описаны отдельно
в [пояснениях по безопасности](docs/security.md).

В инструментах разработчика проверьте:

- **Network → запрос → Response Headers**: CSP, `nosniff` и другие заголовки.
- **Application → Cookies**: `cleaning.sid` и `cookie_notice`, атрибуты
  `HttpOnly` и `SameSite=Lax`.
- В консоли `document.cookie` не показывает эти две cookie.

## Где находится код

| Файл                   | Назначение                                                            |
| ---------------------- | --------------------------------------------------------------------- |
| `src/server.js`        | Express, API, заголовки, CSRF, вход и запуск локального сервера       |
| `src/db.js`            | Подключение Sequelize к файлу SQLite                                  |
| `src/models.js`        | Модели User, CleaningRequest, Session и связь пользователя с заявками |
| `src/session-store.js` | Хранение сессий express-session через модель Session                  |
| `public/*.html`        | Главная, регистрация, вход, кабинет и согласие                        |
| `public/style.css`     | Общие стили и адаптация для телефона                                  |
| `public/app.js`        | Формы, поиск, вывод заявок и уведомление о cookie                     |
| `public/validation.js` | Одинаковые правила полей для браузера и сервера                       |
| `docs/security.md`     | Пояснения к требованиям безопасности и их проверке                    |

Работа с БД идёт через Sequelize: `User.create()`, `User.findOne()`,
`CleaningRequest.findAll()` и другие методы моделей. SQLite-драйвер используется
самой ORM. Таблицы создаются через `db.sync()` без `force` и `alter`, поэтому
существующие пользователи и заявки сохраняются. Связь `User.hasMany(CleaningRequest)`
позволяет получить заявки пользователя также через `user.getRequests()`.

Прямые зависимости: Express, Sequelize, sqlite3, express-session и express-rate-limit.
В `overrides` закреплена исправленная версия транзитивного `uuid` для Sequelize.
Пароли хешируются встроенным `crypto.scrypt`.
Тестовые скрипты и тестовые зависимости в итоговый проект не включены.

Для переноса нужны исходники, `package.json`, `package-lock.json`
и документация. `node_modules` устанавливается командой `npm ci`;
папку `data/` с БД и секретом сессий передавать не требуется.
